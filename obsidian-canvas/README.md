# Obsidian Canvas — картинки на холсты Obsidian напрямую

Скилл для Hermes Agent: кладёт картинки (из URL или локальные файлы) на `.canvas`-холсты Obsidian vault **напрямую через файловую систему** — без Local REST API и плагинов. Заточен под сценарий «агент на сервере + vault синхронизируется через Syncthing»: localhost пользовательской машины с сервера недоступен, а файловая копия vault — доступна.

## Что делает

- **`list`** — находит все `*.canvas` в vault (рекурсивно, пропускает `.obsidian`/`.trash`/`.git`)
- **`create`** — создаёт пустой холст в корне vault (коллизия имён → отказ, не перезапись)
- **`add`** — картинка (URL или файл) → скачивание/чтение → определение формата и натуральных размеров → запись файла в vault → file-нода на холсте с автоматической раскладкой (рядовая сетка: ряд до 1600px, gap 40, высота ноды 300)
- Раскладка читает существующие ноды и никогда не ставит новую поверх них; серия `add` сама выстраивает картинки в ряд/сетку — можно собирать мудборды
- Безопасная запись: tempfile → fsync → atomic replace → chmod 644; после записи verify-after-write по id ноды с повторами (защита от гонки с открытым Obsidian/Syncthing); если файл прямо сейчас синхронизируется (`~syncthing~*`) — вернёт код 5 «повторить позже», а не испортит холст
- Форматы без Pillow: встроенные парсеры заголовков PNG/JPEG/GIF/BMP/WebP/SVG; с Pillow — всё, что он понимает

## Триггеры

- «Добавь картинку <url> на холст <имя> / в canvas»
- «Скинь эти картинки в Obsidian на холст», «собери мудборд из N картинок на новом холсте»
- Любая задача «картинка → .canvas» со стороны агента

Не подходит для: чтения/поиска по vault (скилл `obsidian`), работы через Local REST API (`obsidian-vault-automation`).

## Комплект скриптов

| Скрипт | Назначение |
|---|---|
| `scripts/canvas_cli.py` | весь функционал: `list` / `create NAME` / `add SOURCE (--canvas ПУТЬ \| --new ИМЯ)` |

Вывод каждой команды — одна JSON-строка в stdout (удобно парсить агенту), человекочитаемое — в stderr. Коды выхода: `0` ок, `2` аргументы, `3` проблема canvas (нет/битый/коллизия), `4` источник/сеть, `5` Syncthing занят.

## Быстрый старт

```bash
CLI=~/.hermes/skills/obsidian-canvas/scripts/canvas_cli.py

# все холсты vault'а
python3 $CLI --vault /path/to/vault list

# картинка из интернета → существующий холст
python3 $CLI --vault /path/to/vault add "https://example.com/photo.jpg" --canvas "Boards/Идеи.canvas"

# локальный файл → новый холст в корне vault
python3 $CLI --vault /path/to/vault add ./photo.png --new "Мудборд"
```

Путь vault: флаг `--vault`, иначе `$OBSIDIAN_VAULT`, иначе `~/Sync/ObsidianVault`.
Флаги `add`: `--folder` (папка картинок, дефолт `Canvas Inbox`), `--target-height` (дефолт 300), `--max-attempts` (дефолт 3).

## Требования

- Python 3.8+ (только stdlib; Pillow опционален — расширяет определение размеров экзотических форматов)
- Vault Obsidian, доступный агенту по файловой системе (например, через Syncthing)

## Связь с расширением Obsidian Canvas Clipper

Скилл — «агентская обёртка» того же ядра, что и Chrome-расширение obs-canvas-clipper (картинка из браузера → холст через Local REST API). Константы раскладки, алгоритм поиска свободного места и формат имён `clip--ГГГГММДД-ЧЧММСС--<hash6>.<ext>` совпадают 1:1 — ноды из обоих источников ложатся в одну сетку на общем холсте.
