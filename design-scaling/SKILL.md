# Масштабирование дизайна

Три этапа; начинать нужно с того, который соответствует состоянию проекта:
- **0. ФП + выводы проекта + тексты + фрэнки → ч/б композиционный прототип → первая дизайн-концепция.** Подготовительный этап, когда собственной утверждённой Hi-fi-концепции ещё нет. Агент ищет таблицу эмоциональных и визуальных выводов проекта, затем создаёт редактируемый ч/б прототип по композиции фрэнки непосредственно в текущем Figma-файле. Пользователь самостоятельно редактирует его в этом же файле. После завершения правок агент проверяет актуальную версию и согласует её, после чего разрабатывает цельную Hi-fi-концепцию.
ФП задаёт структуру и содержание, фрэнки — композицию, таблица выводов — эмоциональные и визуальные требования. Фрэнки не является источником чужих цветов, шрифтов, графики или текстов. Подробности —
  `references/stage-0.md`.
- **А. Концепция → правила + UI-kit.** Один раз на проект. После утверждения концепции
  агент измеряет её, записывает правила в `дизайн-правила.md` и собирает UI-kit в Figma.
- **Б. Прототип + тексты (+ фрэнки) → дизайн-макет страницы.** Для каждой новой
  страницы. Агент собирает страницу только из правил и UI-kit. Если есть фрэнки, она
  задаёт композицию блоков, но не значения. Макет собирается на английской версии
  текстов; русская копия — только после согласования английского дизайнером.
  Изображений агент не генерирует: на их месте заглушки с промтом внутри.

Главный принцип: каждое значение на новой странице — из концепции или из правил. Если
концепция на вопрос не отвечает, агент принимает решение сам, но называет его в отчёте
и не выдаёт за правило.

Второй принцип: **каждый цвет в UI-kit и на страницах привязан к цветовой переменной**.
Это заливки, обводки, цвет текста, стопы градиентов, тени, а также скрытые слои и служебные
подложки. Работа не закончена, пока `scripts/color-audit.js` не вернёт `unbound = []`.

Figma — через подключение claude.ai Figma. Перед первым `use_figma` загрузить его скилл
`figma-use`, для UI-kit — ещё `figma-generate-library`, для страницы —
`figma-generate-design`. Выполнять их инструкции как есть.

## Среда исполнения

- **Claude Code** (основной путь): Figma через подключение claude.ai — `use_figma`, `get_screenshot`, `get_metadata`; перед первым вызовом загрузить скилл `figma-use` и выполнять его инструкции как есть.
- **Hermes Agent**: Figma через MCP `figma-console-cloud` (плагин Desktop Bridge). Маппинг инструментов, пейринг, особенности relay и скриншотов — `references/hermes-env.md`; прочитать до первого `figma_execute`. `figma-use` остаётся обязательной прембулой и в Hermes.

## Какой этап и что прочитать

До первого действия прочитать нужные файлы целиком:

| Задача | Читать |
|---|---|
| Создать первую концепцию, если своей утверждённой ещё нет | `references/stage-0.md` + `references/frankie.md` (если есть фрэнки); дополнительно найти таблицу выводов в файлах проекта |
| Снять правила и UI-kit с концепции | `references/stage-a.md` + `references/colors.md` |
| Собрать страницу по прототипу и текстам | `references/stage-b.md` + `references/colors.md` |
| То же, и к странице есть фрэнки | `references/stage-b.md` + `references/frankie.md` + `references/colors.md` |
| Только привязать цвета или проверить привязку | `references/colors.md` |
| Собрать/пополнить базу фрэнки, отобрать кандидатов под блоки ФП | `references/frankie-base.md` |
| Вход страницы — фото рукописного скетча | `references/sketch.md` + `references/stage-b.md` |

Страницу просят, а `дизайн-правила.md` и страницы Figma «UI-kit» нет:
- есть утверждённая собственная концепция — сначала этап А;
- концепции ещё нет — сначала этап 0, затем после утверждения этап А.
Не пытаться выполнить этап Б без дизайн-правил и UI-kit.
Все пути в файлах — от папки скилла.

## Что на входе

| Вход | Откуда |
|---|---|
| Фрейм концепции | Для этапа А/Б: ссылка на фрейм (node-id). Нет ссылки — спросить, есть ли утверждённая концепция. Если нет — предложить этап 0 |
| Функциональный прототип первой/ключевой страницы (этап 0) | фрейм / секция в Figma или `.md`: блоки по порядку и состав каждого |
| Тексты первой/ключевой страницы (этап 0, если есть) | фрейм «Тексты» в Figma или документ; если текстов нет, согласовать временные тексты |
| Фрэнки первой/ключевой страницы (этап 0) | фрейм Figma с фрагментами референсов по блокам; если пользователь уже работает в нужном Figma-файле, самостоятельно найти фрэнки в нём. Не запрашивать ссылку на отдельный фрейм без необходимости |
| Бриф и материалы бренда (этап 0, если есть) | описание проекта, аудитории, позиционирования, желаемого впечатления, логотип, брендбук и существующие ограничения |
| Таблица выводов проекта (этап 0, если есть) | искать в проектных файлах и материалах Figma: эмоции → слой дизайна → конкретные визуальные приёмы; использовать как требования к Hi-fi-концепции |
| Функциональный прототип страницы (этап Б) | фрейм / секция в Figma или `.md`: блоки по порядку и состав каждого |
| Тексты страницы (этап Б, если есть) | фрейм «Тексты» в Figma, `.md`, `.docx`, Google Doc. Часто в нескольких языковых версиях: макет — на английской, русская — для копии после согласования. Есть рядом с прототипом, но ссылку не дали — спросить, брать ли их |
| Фрэнки страницы (этап Б, если есть) | фрейм в Figma: склеенная картинка или набор картинок, фрагменты чужих сайтов сверху вниз по блокам. Лежит рядом с прототипом (часто с именем страницы), но ссылку не дали — спросить, брать ли её |
| `дизайн-правила.md` и страница Figma «UI-kit» (этап Б) | результат этапа А |

Файл правил класть в папку проекта рядом с прототипом. Папки нет — в текущую рабочую
папку, путь назвать в отчёте. В папке уже лежит `дизайн-правила.md` другого проекта
(строка «Источник» ведёт на другой фрейм) — не перезаписывать: положить в подпапку с
именем проекта.

Если отсутствует обязательный функциональный прототип или фрэнки, запросить недостающий материал. Не считать фрэнки заменой функционального прототипа.

## Если собственной концепции ещё нет

Не начинать этап А с фрэнки или с функционального прототипа: сначала выполнить этап 0
по `references/stage-0.md`. Этап 0 сначала создаёт ч/б композиционный прототип по фрэнки, затем первую Hi-fi-концепцию; оба результата согласуются отдельно. Он не заменяет этап А:
формальные правила, переменные, UI-kit и аудит цветов создаются только после утверждения
концепции. Если пользователь просит «сделать всё сразу», сохранить контрольную точку:
показать первую концепцию и получить подтверждение, если пользователь явно не разрешил
продолжить без него.

После создания ч/б прототипа дождаться завершения пользовательских правок. Повторно изучить актуальный фрейм, проверить его соответствие ФП и фрэнки и получить отдельное подтверждение композиции. До подтверждения не переходить к Hi-fi. Перед созданием Hi-fi согласовать визуальное направление с пользователем по правилам `references/stage-0.md`.

## Концепция на внешней библиотеке

Признаки (этап А, шаг 2): `color-audit.js` вернул большой `styled`, у инстансов
концепции `remote = true`, локальных переменных и стилей нет. Привязать такие цвета к
ролям нельзя, пока на узлах висят стили библиотеки. **До сборки UI-kit спросить
дизайнера один раз:** заменить стили и компоненты библиотеки локальными ролями, стилями и
компонентами (рекомендуется — иначе `unbound` не дойдёт до нуля) или оставить их и сдать
черновиком. Ответ «заменить» — по `references/colors.md`, «Концепция на библиотеке».
Ответ «оставить» — компоненты UI-kit и блоки страниц остаются инстансами библиотеки
(не отсоединять, стили не снимать), переменные и роли заводятся только для цветов без
стиля; `styled` из аудита — списком в отчёте, работа сдаётся черновиком (раздел «Отчёт»).
Концепцию не менять при любом ответе.

## Шрифты

Сначала проверить `figma.loadFontAsync` для каждой гарнитуры и начертания концепции.

**Шрифты доступны** — стили UI-kit на тех же гарнитурах. Тексты клонов не пересоздавать:
перевести на локальные стили на месте — `scripts/detach-library.js` (сопоставление
«библиотечный стиль → локальный» и `STYLE_KEY` для текстов без стиля; работает и без
библиотеки). Пункты ниже не нужны.

**Библиотека + шрифты недоступны** — `detach-library.js` (отвяжет инстансы и стили,
тексты на недоступных шрифтах пропустит в `fontBlocked`), затем `restyle-texts.js` по
тому же узлу, затем `bind-colors.js`.

**Шрифты недоступны.** Шрифты, установленные у дизайнера локально, `use_figma` не видит.
Тексты ими нельзя ни создать, ни изменить — даже перекрасить. Установка шрифтов на
компьютер дизайнера агенту не помогает.

- Текстовые стили UI-kit собрать на близких заменах из Google Fonts (с кириллицей),
  оригинал записать в описание стиля.
- Тексты клонов пересоздать скриптом `scripts/restyle-texts.js`, в том же проходе
  привязать их цвета (`references/colors.md`).
- Страницы собирать на заменах. Оригинальные гарнитуры дизайнер ставит в стили в конце —
  только после `color-audit.js` с `unbound = []`.
- В стилях уже стоят оригиналы (`restyle-texts.js` вернул `unavailableStyles`) — стоп:
  попросить дизайнера вернуть замены на время сборки. Самому гарнитуры в стилях не менять.

## Отчёт

- **Что сделано:** перечислить выполненные действия и результаты. Для этапов А и Б приложить ссылки на соответствующие Figma-фреймы и страницы. Для этапа 0 ссылки не формировать и не отправлять: пользователь работает в текущем открытом Figma-файле и уже видит нужные фреймы.
- **Карта блоков** (этап Б): блок → повтор / паттерн / новый → из чего собран →
  фрагмент фрэнки (если был).
- **Фрэнки** (этап Б, если была): фрагмент → блок → что взято → что заменено токенами;
  неиспользованные фрагменты (`references/frankie.md`, «В отчёт»).
- **Изображения** (этап Б): заглушка → блок → что в кадре → стиль промта; где взято
  фото из концепции; строка «Стиль промтов», если составлена заново.
- **Язык** (этап Б): макет на английском; вопрос, делать ли русскую копию. Для копии —
  расхождения английской и русской версий текстов.
- **Тексты** (этап Б): откуда и на каком языке; фрагменты без блока; блоки, где текст
  написан агентом; опечатки в источнике.
- **Цвета:** сколько цветов привязано и сколько осталось (должно быть 0), какие роли
  добавлены, роли-«разнобой».
- **Где выбирал сам:** решение и на какое правило опирался.
- **Разнобой:** значение → где → предложенный канон.
- **Предлагаю добавить в правила:** новые приёмы, появившиеся на странице. В файл
  правил вписывать только после согласия.
- **Что решить дизайнеру:** вопросы списком.

**Черновик.** Работа не закончена (`unbound` не пуст, нет текстов, ждём ответа дизайнера),
а её просят сдать сейчас — сдать с первой строкой отчёта «Черновик, не закончено:» и
списком: что осталось (например, «27 текстов без привязки цвета»), узлы, причина (шрифт
недоступен), что нужно от дизайнера. Готовой не называть.

## Частые ошибки

Ошибки этапов и цвета — в конце каждого файла из `references/`. Общие:

| Ошибка | Как правильно |
|---|---|
| Начал работу, не определив, есть ли утверждённая концепция | выбрать этап 0 или А по состоянию проекта |
| Начал работу, не прочитав файл этапа и `colors.md` | сначала таблица «Какой этап и что прочитать» |
| Вернул оригинальные шрифты до привязки цветов текста | сначала `color-audit.js` = 0, потом гарнитуры |
| Сам поменял гарнитуру в стилях, чтобы скрипт прошёл | попросить дизайнера вернуть замены |
| Пересоздал текст и потерял ширину колонки | переносить `minWidth`/`maxWidth`: в концепциях ими держат 320 и 680 |
| Задал тексту `paragraphSpacing` или межстрочный «как в оригинале» | любое типографское свойство отвязывает стиль — значение вносить в сам стиль |
| Назвал готовым то, что не прошло проверки | сдать черновиком с перечнем, что осталось |
| Взял со фрэнки шрифт, цвет, текст или картинку | фрэнки даёт только композицию, значения — из правил (`references/frankie.md`) |
| Концепция на стилях библиотеки, а агент молча снял стили или молча оставил их | спросить один раз до UI-kit (раздел «Концепция на внешней библиотеке») |
| Пересоздал тексты `restyle-texts.js`, хотя шрифты доступны | шрифты доступны — стиль меняется на месте |
| Перезаписал `дизайн-правила.md` другого проекта | подпапка с именем проекта |
| Задал крупному тексту фиксированную ширину и не проверил переносы | Display-текст молча переносится (5 строк становятся 6): проверить число строк = height/lineHeight и ужимать fontSize циклом, пока не уложится |
| Задал прозрачность пилюли/плашки на frame, а не на paint | `fills:[{...,opacity}]` на самом прямоугольнике, не `frame.opacity` — иначе текст-потомок тоже полупрозрачный |
| Проверил макет только сравнением скриншотов | сначала программная геометрия `scripts/qa-geometry.js` (issueCount = 0), затем vision-сверка |


### Особенность этапа 0: работа в текущем Figma-файле

На этапе 0 пользователь работает непосредственно в открытом Figma-файле. Создавай ч/б прототип в этом файле, не запрашивай и не отправляй ссылки на файл или отдельные фреймы. После создания сообщи только название фрейма и готовность к самостоятельному редактированию. Дождись сообщения пользователя о завершении правок. Затем изучи актуальную версию фрейма и продолжай работу с ней, сохраняя все пользовательские изменения.
