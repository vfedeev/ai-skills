# Формат отчёта

Отчёты этапов А и Б — по этому файлу (у этапа 0 свой раздел «Результат и отчёт» в
`stage-0.md`). Первая строка отчёта — статус, и та же строка — последняя (отчёт читают
с краёв): `Готово.` или `Черновик, не закончено:` + перечень.

- **Что сделано:** перечислить выполненные действия и результаты. Для этапов А и Б —
  ссылки на соответствующие Figma-фреймы и страницы + пути к финальным скриншотам,
  сохранённым в папке проекта. Для этапа 0 ссылки не формировать и не отправлять:
  пользователь работает в текущем открытом Figma-файле и уже видит нужные фреймы.
- **Карта блоков** (этап Б): блок → повтор / паттерн / новый → из чего собран →
  фрагмент фрэнки (если был); по каждой строке — evidence из гейтов (строка аудита).
  Таблица длиннее ~15 строк — в файл, в отчёте сводка и путь.
- **Фрэнки** (этап Б, если была): фрагмент → блок → что взято → что заменено токенами;
  неиспользованные фрагменты (`references/frankie.md`, «В отчёт»).
- **Изображения** (этап Б): заглушка → блок → что в кадре → стиль промта; где взято
  фото из концепции; строка «Стиль промтов», если составлена заново.
- **Язык** (этап Б): макет на английском; вопрос, делать ли русскую копию. Для копии —
  расхождения английской и русской версий текстов.
- **Тексты** (этап Б): откуда и на каком языке; фрагменты без блока; блоки, где текст
  написан агентом; опечатки в источнике.
- **Цвета:** вывод скрипта — `bound`/`unbound` из `color-audit.js` (JSON-выдержка),
  а не пересказ числами агента; какие роли добавлены, роли-«разнобой».
- **Шкалы:** `offScale` из `inventory.js` — пусто или перечень названных позиций.
- **Независимая сверка** (этап Б, шаги 7.5–7.6): кто проверял, вердикты по пунктам
  приёмки pass / fail / unknown, итог sweep по старым страницам.
- **Известные проблемы:** неубранное и не-шум: `unbindable` (NOISE), `fontBlocked`,
  точечно перепривязанные узлы, причины черновика. Дублировать в
  `<проект>/дизайн-статус.md` — при следующей сдаче сверяться со списком, а не находить заново.
- **Где выбирал сам:** решение, на какое правило опирался и отвергнутая альтернатива
  («почему не так»).
- **Разнобой:** значение → где → предложенный канон. Формат реестра: «предложил —
  решил — отказ (с причиной)»; предложение, повторённое в трёх отчётах без решения,
  эскалировать явно, не пересказывать молча.
- **Предлагаю добавить в правила:** новые приёмы, появившиеся на странице; одно и то же
  «сам» в третий раз — сюда же. В файл правил вписывать только после согласия.
- **Что решить дизайнеру:** вопросы списком, каждый с меткой Важно или Мелочь.
  Вопрос требует ответа-решения, молча как инструкция не исполняется. Если вопросов нет —
  строка «вопросов нет», раздувать список искусственно не нужно.

**Черновик.** Работа не закончена (`unbound` не пуст, `offScale` не пуст, `issueCount` не
ноль, нет текстов, лимит циклов исчерпан, ждём ответа дизайнера), а её просят сдать сейчас —
сдать с первой строки отчёта «Черновик, не закончено:» и списком: что осталось (например,
«27 текстов без привязки цвета»), узлы, причина (шрифт недоступен), что нужно от дизайнера.
Готовой не называть.
