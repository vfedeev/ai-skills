# Этап А. Концепция → правила + UI-kit

Один раз на проект. Пути к скриптам и шаблону — от папки скилла. Цвета — по
`references/colors.md`: читать вместе с этим файлом.

1. **Посмотреть.** Скриншот всего фрейма, затем каждой секции отдельно в ширину макета
   (`maxDimension` = ширина фрейма). По скриншоту — характер стиля и повторяющиеся
   приёмы, по цифрам — значения.
2. **Измерить.**
   - `scripts/inventory.js` через `use_figma`: заменить `ROOT_ID` на id фрейма и отправить
     текст файла. Скрипт только читает. Вернёт секции с фонами и отступами, layout grid,
     частоты текстовых стилей, цветов, padding/gap, радиусов, эффектов, x-координаты левых
     краёв текста и пропорции изображений.
   - **Цвета** — `scripts/color-audit.js` по фрейму концепции. В концепции ничего не
     привязано, поэтому `unbound` вернёт все цвета, сгруппированные по «цвет + свойство +
     режим», с примерами мест: стопы градиентов, тени, полупрозрачные варианты, скрытые слои,
     иконки внешних библиотек (`remote`). Это исходник для ролей. `truncated: true` — список
     обрезан: поднять `LIMIT` или проверить фрейм по секциям.
   - Переменные и стили файла — через `get_variable_defs`. Если они есть, правила опираются
     на них, а не на «сырые» значения.
   - **Библиотека.** `color-audit.js` вернул большой `styled`, а инстансы — `remote` —
     концепция на чужой библиотеке. Собрать список её стилей (имя, значение, свойства,
     сколько употреблений) и компонентов (`getMainComponentAsync`: имя, `remote`) и
     задать дизайнеру один вопрос: заменить стили библиотеки локальными ролями,
     стилями и компонентами или оставить и сдать черновиком (`colors.md`,
     «Концепция на библиотеке»). Значения стилей — исходник для «Палитры», ролей и
     текстовых стилей.
   - **Шрифты** — проверить `figma.loadFontAsync` для каждой гарнитуры концепции. Недоступны
     — по `references/fonts.md`. Сказать об этом в первом же отчёте.
3. **Вывести канон.** Для каждой категории: частые значения — шкала. Редкие значения
   рядом с частыми (22 при 20 и 24, Inter среди TT Neoris) — в таблицу «Разнобой»
   с предложенным каноном. Молча не нормализовать: что считать нормой, решает
   дизайнер. У каждого значения — пометка: **изм.** (измерено), **выв.** (выведено
   из закономерности), **реш.** (решение дизайнера, после ответа).
   Значение вне шкалы, без которого не собрать паттерн (шаг строк 35 / 45 при шкале 40,
   хедер от верха 16), — тоже переменная «Отступов» с описанием «изм.» и, если это
   разнобой, «РАЗНОБОЙ: канон — …». Не округлять и не оставлять «сырым» px.
4. **Описать паттерны.** Повторяющиеся устройства блоков: шапка секции, типы карточек,
   кнопки и ссылки, табы, поля, ритм светлых и тёмных секций, работа сетки. У каждого
   паттерна — id эталонного узла в концепции: на этапе Б его клонируют, а не рисуют
   заново.
5. **Записать правила** в `дизайн-правила.md` по `assets/rules-template.md`. Правило
   формулировать так, чтобы его можно было проверить: «заголовок секции — Display M,
   с x=20, на 2 колонки», а не «заголовки крупные». В разделе 7 — строка «Стиль
   промтов»: по ней на этапе Б пишут промты для заглушек изображений. В строку «Источник»
   записать ревизию концепции — версию Figma-файла или хеш вывода `inventory.js`: это
   якорь аппрува (SKILL.md, «Гейты и лимиты»).
6. **Собрать UI-kit** на странице Figma «UI-kit» (нет — завести; концепцию не трогать):
   - переменные: «Палитра», «Цвет», «Отступы», «Радиусы»; scopes задавать явно. Цвет —
     по `colors.md`, «Цветовые переменные»;
   - текстовые стили по ролям из правил: «Display / L», «Текст / M», «Ссылка / CAPS».
     Шрифты недоступны — стили на заменах, оригинал в описании стиля. Концепция на
     библиотеке — локальный стиль = копия библиотечного со всеми свойствами (`fontName`,
     `fontSize`, `lineHeight`, `letterSpacing`, **`textCase`**, `textDecoration`,
     `paragraphSpacing`), в описании — имя библиотечного стиля. Регистр живёт в стиле:
     без `textCase` CAPS-подписи станут строчными. Служебные стили «Промт / L…XXS» для
     заглушек создаёт `scripts/image-prompt.js` при первом запуске;
   - компоненты — **клоны элементов концепции**, превращённые в компоненты и привязанные
     к переменным и стилям. Тексты клонов: шрифты недоступны — `scripts/restyle-texts.js`;
     доступны — стиль меняется на месте. Клон библиотечного инстанса — сначала
     `scripts/detach-library.js` (отсоединит вложенные инстансы, переведёт тексты на
     локальные стили, снимет цветовые стили), потом `createComponentFromNode`; цвета —
     после того, как все компоненты созданы, одним `bind-colors.js` по странице UI-kit
     (последний пункт этого шага). С нуля —
     только то, чего в концепции нет, но что нужно (состояния hover / active / focus /
     disabled / error, тёмный вариант; для полей ввода — состояния валидации и пустого
     значения). Такие варианты помечать в описании компонента: «выведено, не из концепции»,
     и выписывать в раздел 9 правил «Компоненты UI-kit» — этап Б собирает страницы только
     по объявленным состояниям.
   - компонент, нарисованный для фона, которого на странице UI-kit нет (белый текст под
     футер на градиенте, белая кнопка-контур), положить на подложку с этим фоном,
     привязанную к ролям (`декор/…`), — иначе в UI-kit он невидим;
   - рядом — образцы: палитра, шкала текста, шкала отступов. Образцы и подложки тоже
     привязаны к переменным;
   - **привязать цвета** — по `colors.md`, «Привязка цветов», на всю страницу UI-kit.
7. **Отчёт и стоп** (формат — в `references/report.md`). Завести
   `<проект>/дизайн-статус.md` по `assets/status-template.md`: ревизия концепции и цифры
   гейтов (`unbound`, `issueCount`, `offScale`). Этап Б начинать после «утверждаю» —
   аппрув привязан к записанной ревизии. Если прототип передали в том же запросе и просили
   сделать всё сразу — продолжить, но решения по «Разнобою» считать временными и
   перечислить их в отчёте страницы.

## Частые ошибки этапа А

| Ошибка | Как правильно |
|---|---|
| Правила по скриншоту «на глаз» | сначала `inventory.js`, глаз — только для характера и паттернов |
| Округлил разнобой до «правильного» значения без вопроса | в таблицу «Разнобой», решает дизайнер |
| Нарисовал кнопку или карточку с нуля | клонировать эталонный узел концепции |
| Изменил фрейм концепции | концепцию только читать |
| Сделал компонент из клона библиотечного инстанса как есть | сначала `detach-library.js`, иначе внутри останутся стили и инстансы библиотеки |
| Локальный стиль скопировал без `textCase` | копировать все свойства библиотечного стиля |
| Оставил в компоненте «сырой» px, которого нет в шкале | переменная «Отступов» с пометкой «изм.» |
| Привязал «утверждаю» ни к какой ревизии | в строке «Источник» — версия Figma или хеш вывода inventory.js |
| Объявил состояния компонентов, которых нет в разделе 9 правил | реестр состояний в правилах; страница собирается только по нему |
