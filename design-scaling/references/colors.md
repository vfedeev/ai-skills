# Цвета: переменные и привязка

Нужен обоим этапам. На этапе А — оба раздела; на этапе Б — «Привязка цветов», а
«Цветовые переменные» — когда понадобилась новая роль. Пути к скриптам — от папки скилла.

Цель: каждый цвет в UI-kit и на страницах привязан к роли — заливки, обводки, цвет текста,
стопы градиентов, тени, скрытые слои, служебные подложки. Проверка — `scripts/color-audit.js`
с `unbound = []`. Ошибка или пустой вывод скрипта — не зачёт; control case первого аудита
сессии — SKILL.md, «Гейты и лимиты».

## Цветовые переменные

Две коллекции:
- **«Палитра»** — примитивы: каждый уникальный непрозрачный цвет концепции, включая стопы
  градиентов. Имя — тон и ступень по светлоте: 0 — белый, 1000 — самый тёмный, шаг 50
  (`чернила/1000`, `олива/600`). `scopes = []`: в пикерах примитивов не видно, к макету их
  не привязывают.
- **«Цвет»** — роли. К ним привязан каждый элемент. Есть тёмные секции — два режима,
  Светлая и Тёмная: компонент, привязанный к ролям, сам перекрашивается по режиму секции,
  и отдельный «тёмный вариант» не нужен. Тёмных секций нет, а тёмную зону даёт фоновый
  градиент (футер на его насыщенном конце) — режим один; всё, что стоит на тёмном конце
  градиента, — роли `…/инверсия` (`текст/инверсия`, `линия/инверсия`).

Как составить роли — по списку `color-audit.js` с концепции: каждая пара «цвет + где он
стоит» получает роль.

| Группа | Пример | scopes |
|---|---|---|
| `фон/` | `фон/секция`, `фон/карточка` | `FRAME_FILL`, `SHAPE_FILL` |
| `текст/` | `текст/основной`, `текст/второстепенный` | `TEXT_FILL` (+ `SHAPE_FILL` для точек-маркеров) |
| `иконка/` | `иконка/основной` | `SHAPE_FILL`, `STROKE_COLOR` |
| `линия/` | `линия/сетка`, `линия/поле`, `линия/акцент` | `FRAME_FILL`, `SHAPE_FILL`, `STROKE_COLOR` |
| компонент | `кнопка/фон`, `кнопка-стекло/текст` | по свойству |
| `фото/`, `декор/` | `фото/затемнение`, `декор/градиент-1` | `FRAME_FILL`, `SHAPE_FILL` |
| `служебное/` | `служебное/подложка` — только UI-kit | `FRAME_FILL` |

- Роль называется по назначению, а не по цвету: `текст/основной`, а не `белый`.
- Одна роль на один тип элемента: «Price», плейсхолдер поля и неактивный таб с одинаковым
  цветом — одна роль `текст/второстепенный`. Отдельная роль — только если элемент в другой
  теме ведёт себя иначе.
- Значение роли — алиас на примитив палитры. Полупрозрачное значение (`#101010 @12%`) —
  rgba прямо в роли: алиас не умеет менять прозрачность. Примитивов с альфой не заводить.
- Элемент есть в концепции только в одной теме (обводка цены только на тёмной карточке) —
  значение для второй темы вывести: инверсия пары «текст / фон» с той же прозрачностью.
  В описании роли — «выв.».
- Цвета под изображениями (подложка, градиент под фото) — `фото/подложка…`; прозрачные
  концы градиентов — `декор/прозрачный`.
- Элементу, который не меняется с темой (текст поверх фото, стеклянная кнопка), — своя роль
  с одинаковым значением в обоих режимах. Иначе он перекрасится в тёмной секции.
- Компоненту, чьи цвета не совпадают с общими ролями, — роли своей группы: `кнопка-стекло/…`.
- Разнобой (линии 15% при 12%) — **отдельная роль** с описанием «РАЗНОБОЙ: … канон —
  `линия/сетка`». Тогда всё привязано, макет не изменился, а дизайнер решает: сделать
  роль алиасом канона или оставить.
- У каждой роли — `description`: где применяется.

## Концепция на библиотеке

Цвета концепции заданы цветовыми стилями чужой библиотеки (`styled` в аудите, стили
`remote`), и дизайнер согласился заменить их ролями (SKILL.md, «Концепция на внешней
библиотеке»).

1. «Палитра» — из значений библиотечных стилей (каждый непрозрачный цвет, стопы
   градиентов). Роли — по местам употребления, как обычно; имя библиотечного стиля —
   в описании роли («из стиля Dark purple»).
2. На каждом клоне (UI-kit, страница) — `scripts/detach-library.js` **до**
   `bind-colors.js`: он снимает цветовые стили, цвет остаётся «сырым», и `bind-colors.js`
   его привязывает. Без этого шага узлы со стилем попадут в `styled` и останутся
   непривязанными.
3. Переменные библиотеки на узлах (`elsewhere` в аудите) `bind-colors.js` перепривязывает
   к ролям сам.
4. Концепцию не трогать: стили библиотеки в ней остаются.
5. Ответ дизайнера «оставить» — ничего не заменять: компоненты UI-kit и блоки страниц
   остаются инстансами библиотеки (не отсоединять, стили не снимать), переменные и роли
   заводятся только для цветов без стиля; `styled` из аудита — списком в отчёт, работа
   сдаётся черновиком.

## Привязка цветов

`scripts/bind-colors.js` подбирает роль по цвету, прозрачности, режиму секции и scopes.
Он привязывает заливки, обводки, тексты по сегментам, стопы градиентов и тени. Порядок:

1. **Режимы.** Задать режим фрейму страницы и каждой секции, где он отличается
   (`setExplicitVariableModeForCollection`). Иначе белый текст тёмной секции привяжется
   к светлой роли того же цвета. Клон из тёмной секции, лежащий в UI-kit в режиме по
   умолчанию, — указать в `DRAWN_IN` (`{ '<id>': 'Тёмная' }`).
2. **Тексты** — сначала `scripts/restyle-texts.js` (если шрифты концепции недоступны).
3. **Запуск.** Сначала `DRY_RUN = true` (он проверяет и шрифты), потом по-настоящему.
   Один вызов — одна страница: скрипты остановятся, если ROOT_IDS с разных страниц.
   Порядок: страница UI-kit, потом макеты страниц — иначе инстансы получат переопределения
   вместо наследования.
4. **Разбор результата DRY_RUN** — всё исправить до настоящего запуска:
   - `missing` — цвета без роли. Закрыть каждую строку: новая роль по таблице выше или
     режим секции (`otherMode` не пусто — почти всегда незаданный режим);
   - `picked` — где выбирал из нескольких ролей. Строка с `byGroup: false` верна, если
     элемент меняется вместе с темой. Если элемент стоит поверх фото или стекла, ему нужна
     роль группы компонента (`кнопка-стекло/текст`);
   - `usage` — роль → узлы. Просмотреть целиком: совпадение по цвету не гарантирует смысл.
     Неверная роль → завести роль под этот тип элемента → добавить её префикс в `PREFER`.
     Уже привязанное перепривязать через `REBIND`. Один узел того же типа и цвета должен
     получить другую роль (плашка-прямоугольник `фон/акцент` среди квадратов-маркеров
     `иконка/основной`) — `REBIND` по типу его не отделит: после запуска перепривязать
     этот узел точечно по id;
   - `failed` с «font could not be loaded» — текст на недоступном шрифте. Сначала
     `restyle-texts.js`. Если он вернул `unavailableStyles` (в стилях уже оригинальные
     гарнитуры) — **стоп**: попросить дизайнера вернуть замены в эти стили на время сборки.
     Самому гарнитуры в стилях не менять. До ответа работа сдаётся только черновиком
     (`references/report.md`, «Черновик»);
   - `styled` — цвет из цветового стиля: стиль не снимать молча, спросить дизайнера.
     Стили библиотеки, и дизайнер ответил «заменить» — `detach-library.js` по узлу и
     DRY_RUN снова (раздел «Концепция на библиотеке»);
   - `unbindable` — шум (NOISE): Figma не даёт его привязать, перечислить в отчёте.
5. **Проверка** — `color-audit.js` по тем же узлам: `unbound = []`. Цвета внутри инстансов
   внешних библиотек (`remote`) привязываются переопределением — тоже до нуля.
   «Объяснить в отчёте» вместо привязки нельзя: исключения — только `unbindable`.
6. **Лимит.** bind→audit по одной секции — не более 3 итераций; два неудачных REBIND
   одного узла — пересобрать секцию из чистого клона, не накладывать третий точечный
   патч. Лимит исчерпан — черновик с перечнем причин (SKILL.md, «Гейты и лимиты»).
   После принятия страницы любая правка ролей/компонентов UI-kit — sweep по старым
   страницам (`stage-b.md`, шаг 7.6).

Новые элементы, которые агент создаёт сам, привязывать сразу при создании, по имени роли:
`setBoundVariableForPaint(paint, 'color', роль)`. В `paint.color` класть фактическое
значение роли, а не серую заглушку: на клонах Figma иногда рисует заглушку, хотя
переменная привязана (аудит проходит, а на скриншоте серое). Стоп градиента:
`boundVariables: { color: { type: 'VARIABLE_ALIAS', id } }` прямо в `gradientStops`.
Тень: `setBoundVariableForEffect`.

## Частые ошибки с цветом

| Ошибка | Как правильно |
|---|---|
| Для цвета есть роль, но элемент не привязан («сделаю потом») | привязка — часть сборки, а не финальный шаг |
| Привязал белый текст тёмной секции к светлой роли того же цвета | сначала режим секции, потом привязка |
| Роль по цвету («белый», «чёрный 12%») | роль по назначению: `текст/основной`, `линия/сетка` |
| Привязал элемент к роли с подходящим цветом, но чужим смыслом | смотреть `usage`; нет подходящей роли — завести |
| Запустил по-настоящему, когда в DRY_RUN `failed` или `missing` не пусты | сначала разобрать DRY_RUN до нуля |
| Аудит по ROOT_IDS с разных страниц | один вызов — одна страница |
| Запустил `bind-colors.js` по клону библиотечного узла, всё ушло в `styled` | сначала `detach-library.js` |
| Завёл режим «Тёмная», потому что футер на тёмном градиенте | тёмных секций нет — один режим, роли `…/инверсия` |
| Аудит прошёл, а на скриншоте элемент серый | в paint класть фактическое значение роли |
