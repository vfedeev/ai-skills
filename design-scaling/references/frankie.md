# Фрэнки страницы

Фрэнки — набор фрагментов чужих сайтов, разложенных поблочно сверху вниз, чтобы задать
примерный визуальный образ будущей страницы. Обычно это склеенная картинка (фрейм без
слоёв) или фрейм с отдельными картинками. Подписей у фрагментов, как правило, нет.

Читать на этапе Б вместе с `stage-b.md`, если к странице приложена фрэнки. Нет фрэнки —
этот файл не нужен, этап Б идёт как обычно.

## Кто что решает

| Что | Источник |
|---|---|
| Состав страницы: блоки, порядок, количество карточек и пунктов | прототип |
| Тексты | тексты страницы (или пишет агент, `stage-b.md`, шаг 5) |
| Композиция блока: раскладка по колонкам, масштабный контраст, где фото и какое оно относительно текста, приём подачи (строки списка с фото, сетка ячеек, слово на всю ширину) | фрэнки |
| Токены: гарнитуры и текстовые стили, цвета, отступы, радиусы, сетка, компоненты | правила и UI-kit |
| Повторные блоки (хедер, футер, форма) | концепция — фрэнки для них не используется, даже если там есть похожий блок |

Фрэнки даёт **устройство блока, а не значения**. Со скриншота фрэнки не берут ни одного
шрифта, цвета, размера в px, иконки, картинки или текста.

## Порядок работы

1. **Снять в полном разрешении.** `get_screenshot` по фрейму фрэнки с `maxDimension` =
   большей стороне фрейма (`original_height`). Скачать PNG по `curl` из ответа в папку
   scratchpad.
2. **Нарезать на фрагменты.** Границы — по резкой смене фона, шрифта, сетки (швы между
   сайтами). Каждый фрагмент вырезать и посмотреть отдельно:
   `sips -c <высота> <ширина> --cropOffset <y> <x> full.png --out frag-01.png`
   (порядок аргументов: сначала y, потом x; без `--cropOffset` sips режет от центра).
   Фрэнки — фрейм с отдельными картинками — скриншот каждой картинки по её id.
3. **Описать каждый фрагмент** одной строкой таблицы:
   `№ | что это по смыслу | композиция в колонках концепции | ведущий приём | что не
   переносится на токенах`.
   Композицию описывать в долях и колонках, а не в пикселях фрэнки: ширина фрэнки
   и концепции обычно разная («заголовок на всю ширину, под ним 4 ячейки по 3 колонки
   с линиями между ними»). Верхняя полоска с логотипом и меню чужого сайта — это его
   хедер, а не приём: пропустить.
   Композиция снимается геометрией, а не на глаз: метод скилла `ref-layout-xray`
   (`detect_blocks.py` → боксы элементов; число колонок — по ряду карточек; линии
   контейнера — по пикам левых/правых краёв; силовая линия — по тесту непрерывности).
   Vision — второй метод и только для семантики фрагмента (что за элемент), не для
   чисел: vision систематически врёт в колонках и выравниваниях.
4. **Сопоставить с блоками прототипа** — самостоятельно, без остановки на вопрос.
   Сначала по смыслу (фото интерьера → «фото интерьера и экстерьера», абзац «Profile» →
   «об основателе», строки-ссылки → список новостей), потом по порядку. Один фрагмент
   может задавать несколько блоков, один блок — опираться на два фрагмента.
   - Блок без подходящего фрагмента — обычный путь `stage-b.md`, шаг 3.
   - Фрагмент без блока в прототипе — блок не строить, фрагмент в отчёт.
   - Повторный блок (хедер, футер) — из концепции, фрагмент в отчёт как «не использован».
   - Сомнительное сопоставление — выбрать лучшее и назвать в «Где выбирал сам».
   - Фрагмент взят частично (ячейки — да, слово на всю ширину над ними — нет, потому что
     такое слово на странице уже есть) — в отчёте обе части: что взято и что нет.
5. **Перевести приём на токены.** Композицию переносить, значения брать из правил:
   - *смешение гарнитур* (гротеск + антиква в одной фразе) — контраст внутри стилей
     концепции: начертание, регистр, размер. Вторую гарнитуру не заводить;
   - *акцентная плашка, цветное пятно* — ближайшая роль из коллекции «Цвет». Новый цвет
     не заводить;
   - *слово на всю ширину, сверхкрупный заголовок* — самый крупный Display-стиль
     правил. Больше шкалы не делать;
   - *плашка-«пилюля», рамка, линии* — радиусы и обводки из шкалы; есть компонент
     UI-kit с таким устройством — брать его;
   - *мини-фото внутри строки или фразы* — `scripts/inline-photo-gaps.js` (окно в тексте +
     заглушка поверх, место окна измеряется); пропорция — ближайшая из правил, высота ≈
     межстрочный;
   - *стопка фото* — заглушки или фото из концепции (`stage-b.md`, шаг 6) в ближайшей
     пропорции; положение, наклон и масштаб относительно текста — по фрэнки (наклон —
     в «Где выбирал сам»: шкалы для него нет); тени не добавлять, если их нет в правилах;
   - *ячейка с подписью и стрелкой*, а подписи в текстах нет — подпись не выдумывать:
     на её место маркер или другой приём подписи из концепции;
   - *раскладка* — переложить на колонки и гаттер концепции; отступы — из шкалы.
   Приём не держится без нового токена (нужна вторая гарнитура, новый цвет, размер вне
   шкалы) — собрать ближайший вариант на токенах и записать в «Предлагаю добавить в
   правила» с пометкой «из фрэнки, фрагмент N».
6. **Количество — из прототипа.** Во фрэнки 3 строки списка, а в прототипе «6–12
   карточек» — повторить строку по приёму фрэнки до количества из прототипа. Во фрэнки
   4 ячейки, а категорий 7 — разложить 7 по тому же устройству в пределах сетки.
7. **Проверить** (вдобавок к `stage-b.md`, шаг 7). Сначала программная геометрия —
   `scripts/qa-geometry.js` по собранным блокам (issueCount = 0), затем скриншот каждого
   такого блока рядом с его фрагментом фрэнки — композиция узнаётся. И рядом с концепцией —
   тот же стиль: шрифты, цвета, ритм. Блок похож на фрэнки по шрифтам и цветам больше, чем на
   концепцию, — ошибка: вернуть токены. Vision-сверку вести по контракту скилла
   `structured-image-analysis`; после 2 таймаутов менять вход (thumbnail ≤1000px, короче
   вопрос), а не долбить повтор.

## В отчёт

Раздел **«Фрэнки»**: таблица `фрагмент → блок прототипа → что взято (композиция, приём)
→ что заменено токенами`, а также неиспользованные фрагменты и причины.

## Частые ошибки

| Ошибка | Как правильно |
|---|---|
| Взял со скриншота фрэнки шрифт, цвет, иконку | только токены и компоненты UI-kit |
| Перенёс пиксели фрэнки в значения страницы | геометрию фрэнки измеряют только для относительных пропорций и колонок; значения в px — из правил |
| Добавил блок, потому что он есть во фрэнки | состав только из прототипа, лишний фрагмент — в отчёт |
| Сократил число карточек до количества во фрэнки | количество из прототипа, приём повторить |
| Перенёс тексты или картинки из фрэнки | это чужие сайты: тексты — по `stage-b.md`, шаг 5, фото — шаг 6 |
| Перерисовал хедер или футер по фрэнки | повторные блоки — клон из концепции |
| Завёл вторую гарнитуру или новый цвет ради приёма | собрать на токенах, новое — в «Предлагаю добавить в правила» |
| Смотрел фрэнки только целиком, уменьшенной | полное разрешение и нарезка по фрагментам |
