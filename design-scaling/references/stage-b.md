# Этап Б. Прототип + тексты (+ фрэнки) → дизайн-макет страницы

Для каждой новой страницы. Нужны `дизайн-правила.md` и страница Figma «UI-kit» — результат
этапа А; нет их — сначала этап А. Пути к скриптам — от папки скилла. Привязка цветов —
по `references/colors.md`: читать вместе с этим файлом. Есть фрэнки страницы — ещё
`references/frankie.md`: шаги ниже с пометкой «Фрэнки» выполнять по нему.

1. **Прочитать прототип и тексты.** Из прототипа — блоки по порядку и состав каждого:
   элементы, количество карточек и пунктов, кнопки. Количество — обязательство, а не
   пример. Исключение одно: пунктов в тексте больше (шаг 2). Из текстов — содержание и
   иерархия: начертание и размер (жирный — заголовок), пустые строки, порядок.
   Иерархия не размечена (категории и пункты одним начертанием) — разобрать по смыслу и
   сверить с количеством в прототипе («7 категорий»). Число не сходится — показать разбор
   «категория → пункты» дизайнеру и спросить до сборки. Сходится — разбор в отчёт.
   **Фрэнки:** снять в полном разрешении, нарезать на фрагменты и описать каждый
   (`frankie.md`, шаги 1–3).
2. **Сопоставить тексты с блоками.** Каждому фрагменту текста — блок прототипа:
   заголовок и лид страницы → hero, категории → табы, пункты → карточки или строки списка.
   - **Язык макета — английский.** Тексты есть на английском — собирать на них, даже если
     рядом есть русская версия. Русскую копию делать только после согласования
     английского макета дизайнером (шаг 9). Английской версии нет — спросить: перевести
     или собрать на том языке, что есть.
   - Hero в прототипе нет — заголовок и лид страницы поставить в шапку первого
     контентного блока (метка / заголовок / описание по паттерну «Заголовок секции»).
     В отчёте — в «Где выбирал сам».
   - Пунктов в тексте больше, чем карточек в прототипе, — показать все пункты: повторить
     карточку, строку или колонку по паттерну блока. Текст не сокращать, чтобы влезть.
   - Пунктов в тексте меньше минимума прототипа («6–12 карточек», а новостей 3) — взять
     минимум диапазона, недостающие пункты написать самому в формате текстовых (шаг 5) и
     перечислить в отчёте как написанные агентом.
   - Текст и прототип расходятся в подписи («[BUTTON: All news]» в текстах, «кнопка Load
     more» в прототипе) — на экран текст, расхождение — в «Что решить дизайнеру».
   - Пункт текста сам содержит поля карточки («April 2024: Artist … was shortlisted») —
     разделить по явному разделителю (двоеточие, тире) на поля из прототипа (дата,
     заголовок), слова не менять; разбивку назвать в отчёте.
   - Табы, фильтр, слайдер: в макете активна первая категория, на странице — её пункты.
     Каждую следующую категорию — отдельным фреймом-состоянием рядом со страницей, только
     изменившийся блок: «<Страница> / Дизайн / Таб: <категория>».
   - Фрагмент, которому нет блока в прототипе, — блок не придумывать, фрагмент в отчёт.
   - Блок прототипа без текста — текст написать самому (шаг 5) и пометить в отчёте.
   - Дизайнер сам просит сократить — не выбирать пункты за него: попросить список, что
     убрать, или предложить вариант со всеми пунктами.
3. **Карта блоков.** Для каждого блока выбрать источник:
   - **повтор** — такой блок есть в концепции (хедер, отзывы, форма, футер): клонировать
     секцию и поменять контент под эту страницу;
   - **паттерн** — похожего блока нет, но есть подходящее устройство: собрать по
     паттерну из правил;
   - **новый** — собрать из компонентов UI-kit по разделу «Новые блоки» правил.
   Состав повторного блока в прототипе и в концепции может различаться: расходящиеся
   элементы — в отчёт.
   **Фрэнки:** сопоставить фрагменты с блоками самостоятельно, без вопроса дизайнеру
   (`frankie.md`, шаг 4). У блока с фрагментом источник — «паттерн» или «новый», а
   композиция — по фрагменту. Повторные блоки остаются клонами концепции.
4. **Собрать.** Фрейм «<Страница> / Дизайн» правее концепции, ширина — как у концепции.
   Фрейм с таким именем уже есть — спросить: обновить его или собрать «<Страница> /
   Дизайн v2» рядом.
   Новые элементы — только инстансы UI-kit, текстовые стили и переменные, без «сырых»
   hex и px. Порядок для каждой секции: клонировать → задать режим темы
   (`setExplicitVariableModeForCollection`) → тексты (`scripts/restyle-texts.js`, если
   шрифты недоступны; клон библиотечного узла — `scripts/detach-library.js`) →
   `scripts/bind-colors.js` (по `colors.md`, «Привязка цветов»).
   Повторяющийся элемент нового блока с изображением внутри (строка новости с фото) —
   собирать фреймами на токенах, не инстансами: промт в заглушку внутри инстанса не
   вставить (шаг 6). Устройство такого элемента — в «Предлагаю добавить в правила» как
   кандидат в компонент UI-kit.
   Блок, у которого в концепции есть контекст (например, светлая шапка поверх фото в
   hero), проверить в новом окружении и выбрать вариант компонента.
   **Фрэнки:** приём фрагмента собирать на токенах правил, количество брать из
   прототипа (`frankie.md`, шаги 5–6).
5. **Тексты.** Есть тексты страницы — ставить дословно: не переписывать, не сокращать,
   не переводить. Опечатки не исправлять молча, а вынести в отчёт. Служебная разметка
   автора текстов — не текст: «[BUTTON: All news]» → на кнопке «All news». Заглушки
   данных в скобках («[Name]», «[First Name Last Name]») оставлять на экране как есть и
   перечислить в отчёте — их заменит заказчик. Текста нет — написать
   на английском, правдоподобно и по составу из прототипа. Описание блока в
   прототипе («Список услуг по категориям») — это задача, а не текст на экран.
6. **Изображения.** Брать из концепции, только если совпадает смысл. Иначе — заглушка
   с промтом внутри. Картинки не генерировать, даже если инструмент генерации доступен.
   - **Заглушка** — фрейм в пропорциях из правил (раздел 7), заливка привязана к роли
     (`фото/подложка` или ближайшая по `colors.md`), радиус — из шкалы.
   - **Промт** — на английском, из двух частей: *что в кадре* (по смыслу блока и
     текстам страницы) + *как снято* — общая строка «Стиль промтов» из раздела 7
     правил, одинаковая для всех картинок страницы. В конце — пропорция заглушки
     («16:9»). Строки «Стиль промтов» в правилах нет — составить её по фото концепции
     (обработка, свет, тон, кадр), использовать и предложить добавить в правила.
   - **Вставка** — `scripts/image-prompt.js`: кладёт внутрь заглушки текст
     «Фото: что в кадре · пропорция» + промт и подбирает самый крупный стиль
     «Промт / …», при котором текст влезает. Чем меньше заглушка, тем мельче стиль;
     размер шрифта руками не задавать. `overflow: true` — сократить промт (не подпись)
     и запустить снова. Ошибка «инстанс» — заменить инстанс заглушкой-фреймом.
     `TEXT_ROLE` — тёмная роль текста, контрастная к заливке заглушки.
   - **Крошечная заглушка** (меньшая сторона < 150 px, мини-фото в строке) — полный промт
     не влезет даже в «Промт / XXS». Сокращать сначала «что в кадре», потом строку стиля
     до 3–4 первых признаков (свет, тон); пропорцию оставить. Такие заглушки — в отчёт.
     Не влезло и так — внутри оставить подпись и «что в кадре · пропорция», а полный
     промт дать в таблице «Изображения» отчёта.
   - **Мини-фото внутри строки текста** («Лид с врезками», приём фрэнки) — только
     `scripts/inline-photo-gaps.js`: он вставляет в текст окно из пробелов и измеряет его
     место. Позицию окна на глаз не подбирать. Вставленные пробелы — в отчёт.
7. **Проверить.**
   - `scripts/inventory.js` по новому фрейму: в выводе `offScale` — непривязанные
     паддинги/гапы/радиусы и тексты без стиля. Каждую позицию сверить со шкалами правил
     и привязать к переменной или назвать в отчёте. Цель: `offScale` пуст или каждая
     позиция названа.
   - `scripts/color-audit.js` по фрейму страницы: `unbound = []`.
   - Количества: карточки, пункты и строки по блокам соответствуют обязательствам
     прототипа (шаг 1); расходится — черновик, а не «готово».
   - Длинный вывод аудита/инвентаря сохранять в файл рядом со статус-файлом; в контексте
     и отчёте — счётки и список позиций, не JSON-дампы.
   - Каждый фрагмент текстов есть на странице или назван в отчёте.
   - Скриншот страницы рядом с концепцией: текст не обрезан, нет наложений, ритм
     секций и сетка совпадают. Длинные реальные тексты чаще ломают вёрстку, чем рыба.
   - **Фрэнки:** каждый блок с фрагментом рядом с этим фрагментом — композиция
     узнаётся, а шрифты и цвета взяты из концепции (`frankie.md`, шаг 7).
   - Каждая заглушка с промтом, `image-prompt.js` без `overflow` и ошибок.
   - Финальные скриншоты страницы — сохранить в папку проекта, пути в отчёт
     (доказательство приёмки, а не вложение в чат).
7.5. **Независимая сверка** — отдельный read-only проход без контекста сборки (новая
   сессия или субагент): дать `дизайн-правила.md`, карту блоков, скриншоты страницы —
   и ничего авторского («почему я так выбирал» не передавать). Вердикт по каждому пункту
   приёмки (SKILL.md, «Гейты и лимиты»): pass / fail / unknown. Обязательно: первая
   страница проекта, страницы после отвязки библиотеки, режим «сделай всё сразу»; на
   остальных — по усмотрению, в отчёте назвать, кто проверял.
7.6. **Sweep.** Если в ходе сборки завёл или перепривязал роль либо компонент UI-kit —
   прогнать `color-audit.js` + `qa-geometry.js` по ранее принятым страницам проекта
   (один вызов — одна страница); находки — в «Известные проблемы» и статус-файл.
8. **Отчёт** (формат — в `references/report.md`). Обновить `<проект>/дизайн-статус.md`:
   статус страницы, цифры гейтов, известные проблемы, открытые вопросы, счётчик
   «где выбирал сам». Состав страницы не перестраивать за дизайнера:
   замечания о том, что прототип или тексты не складываются в стиль, — в отчёт.
   В конце отчёта — вопрос: согласован ли английский макет и делать ли русскую копию.
9. **Русская копия — только после согласования.** Дизайнер утвердил английский макет —
   клонировать «<Страница> / Дизайн» (и фреймы-состояния табов) правее, имя
   «<Страница> / Дизайн RU». В клоне заменить каждый текст на соответствующий
   фрагмент русской версии — дословно, по той же разметке «фрагмент → блок», что и
   в шаге 2. Промты в заглушках остаются английскими, подпись «Фото: …» — русская.
   Русский текст обычно длиннее на 15–30 %: до клонирования сохранить английские
   скриншоты секций как базу; после замены снова пройти шаг 7 целиком и сверить с базой
   (visual regression). Русский текст ломает блок — менять блок по правилам, а не текст. Расхождения версий (в русской
   нет фрагмента или он лишний) — в отчёт. Русской версии текстов нет — спросить:
   перевести самому или ждать текстов.

## Частые ошибки этапа Б

| Ошибка | Как правильно |
|---|---|
| На новой странице «сырые» hex и px | только переменные, стили и инстансы |
| Клонировал секцию концепции и оставил её цвета как есть | клон всегда через `bind-colors.js`, потом `color-audit.js` = 0 |
| Переписал или сократил тексты страницы, чтобы влезли | тексты дословно, менять блок, а не текст |
| Выкинул пункты, которым «не хватило» карточек | повторить карточку по паттерну, все пункты на странице |
| 4 карточки при «4–5» в прототипе без объяснения | число — в отчёт, если выбрал из диапазона |
| Добавил блок, которого нет в прототипе | только блоки прототипа; нехватку назвать в отчёте |
| Подменил фото в инстансе и затемнение стало глухим | при замене заливок сохранять `opacity` слоя затемнения |
| Решил, что фото «не грузится», по скриншоту | сначала посмотреть все заливки узла: частая причина — непрозрачный слой поверх |
| Есть фрэнки, а блоки собраны только по паттернам концепции | фрагменты сопоставлены с блоками, композиция взята из фрэнки (`frankie.md`) |
| Собрал макет сразу на русских текстах или обе версии разом | сначала английский макет, русская копия — после согласования (шаг 9) |
| Пустая заглушка или подпись без промта | в каждой заглушке промт через `image-prompt.js` |
| Задал размер шрифта промта руками, чтобы влез | только стили «Промт / …», подбирает скрипт; не влез — сократить промт |
| В каждом промте свой «стиль съёмки» | общая строка «Стиль промтов» из правил для всех картинок |
| Сгенерировал картинку, раз инструмент есть | только заглушка и промт |
| В тексте 3 новости при «6–12» в прототипе — поставил 3 | минимум диапазона, недостающие написать и пометить |
| Поставил подпись из прототипа вместо подписи из текстов | на экран — текст, расхождение — дизайнеру |
| Собрал строки с фото инстансами, промты не вставились | повторяющийся элемент с фото — фреймы на токенах |
| Подобрал x мини-фото в строке на глаз | `inline-photo-gaps.js` измеряет окно |
| Перепривязал роль UI-kit и не перепроверил принятые страницы | sweep, шаг 7.6: все страницы проекта |
| Чинил один узел в третий-четвёртый раз | лимит: два провала → пересобрать секцию из чистого клона |
| Сдал первую страницу проекта без независимой сверки | шаг 7.5 для первой страницы обязателен |
