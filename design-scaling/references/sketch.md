# Вход — скетч от руки (фото)

Альтернативный вход композиции вместо фрэнки (этап 0 или Б). Скетч переносит
композицию, иерархию, плотность и зонирование; размеры, состояния, адаптив и
микротипографию переносят правила и UI-kit — никогда не сам скетч.

## Пайплайн

1. **Фото скетча → структурированное чтение**: блок-зоны, порядок, стрелки, подписи.
   Читать по контракту скилла `structured-image-analysis` (структурный вопрос, не «опиши картинку»).
2. **Перевод зон в паттерны** правил/UI-kit → «скетч-протокол» текстом: зона → что собираем,
   спорные места — списком вопросов.
3. **Утверждение протокола** — одна итерация, до рисования. Без «да» не собирать.
4. **Сборка** из правил и UI-kit: skeleton секций с placeholder → по одной секции за шаг →
   контент в слоты; всегда return node IDs.
5. **Скриншот результата против скетча** → правки до совпадения композиции (не до «нравится»).

## Правила

- Зона вне словаря паттернов/правил — вопрос к дизайнеру, а не импровизация.
- Значения (кегли, отступы, радиусы, цвета) — из правил; со скетча снимаются только доли и расположение.
- Программный QA после сборки: `scripts/qa-geometry.js` (issueCount = 0), затем vision-сверка со скетчем.
