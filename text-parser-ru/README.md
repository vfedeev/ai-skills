# Text Parser RU — чистка текста по образцу

Скилл для Hermes Agent: приводит «грязный» текст (выгрузки из Word/PDF, OCR, дампы чатов, кривой копипаст) к чистовому форматированию **по эталону, который пользователь сделал руками**. Не переписывает текст — правит только оформление.

## Что делает

- **Анализирует эталон**: пользователь даёт кусок «как надо» — скилл выводит из него конкретные правила (что склеить, что удалить, какие символы заменить), а не действует «по общим рекомендациям»
- **Применяет правила конвейером**: один вызов `pipeline.py` = нормализация → правила → типографика → регресс-чек → txt/docx
- **Спрашивает, а не угадывает**: спорные места собираются в один список вопросов; смысловые правки — только по явной просьбе
- **Помнит задачи**: каждая завершённая чистка фиксируется в `references/log/`, повторные тексты того же клиента/формата идут по готовым правилам

## Триггеры

- «Почисти текст / приведи к нормальному виду / убери переносы и ¶ вот по этому образцу»
- «Убери иероглифы / китайские символы» — пресет CJK, эталон не нужен
- «Поставь правильные кавычки-ёлочки, тире, пробелы» — пресет русской типографики

Не подходит для: стилистического переписывания, извлечения данных в таблицу, транскрибации.

## Архитектура

```
сырой текст + эталон
   │  LLM: индукция правил (эталон = ТЗ)   ← единственная «мыслящая» фаза
   ▼
список правил → профиль класса (references/profiles/<класс>.py)
   │  скрипт: детерминированное исполнение ← сюда токены не жгутся
   ▼
pipeline.py: base-нормализация → run(профиль) → ТИПО → POST
             → регресс-чек нулями → --clean.txt (+ --docx: ¶/↵/жирный)
```

LLM — «компилятор» ТЗ в regex-правила; скрипт — «машинный код». Exit code 1 = чек провален, результат не сдаётся. Второй текст того же класса — один вызов конвейера без анализа.

## Комплект скриптов

| Скрипт | Назначение |
|---|---|
| `scripts/pipeline.py` | однопроходный конвейер (профиль + пресеты + чек + docx) |
| `scripts/typo_ru.py` | пресет русской типографики: «ёлочки»/„лапки", тире/дефис/dash-диапазоны, пробелы |
| `scripts/strip_cjk.py` | пресет CJK: аудит Unicode-групп, маппинг полноширинных, удаление письмен; детект mojibake |
| `scripts/clean_text.py` | каркас RULES-конвейера с счётчиками |
| `scripts/build_docx_schedule.py` | txt→docx с Word-семантикой: пустая строка = ¶, перевод = ↵ (Shift+Enter), опция — жирные строки по regex |

## Требования

Python 3.8+ (только stdlib, зависимостей нет). pandoc — опционально, для конвертаций не-Word.

## Установка

```bash
git clone https://github.com/vfedeev/ai-skills.git
cp -r ai-skills/text-parser-ru ~/.hermes/skills/
```

Или из ZIP-архива на странице [Releases](https://github.com/vfedeev/ai-skills/releases).

## Быстрый старт

```bash
# типографика одного текста, эталон не нужен
python3 scripts/typo_ru.py вход.txt выход.txt --attach-short

# аудит иероглифов
python3 scripts/strip_cjk.py вход.txt            # счётчики по группам Unicode
python3 scripts/strip_cjk.py вход.txt выход.txt --remove --map

# чистка по образцу (путь агента): профиль класса + полный конвейер
python3 scripts/pipeline.py raw.txt references/profiles/afisha.py out --attach-short --docx
```

## Формат отдачи

`.txt` не перевозит мягкие переносы (↵ vs ¶), неразрывные пробелы, разные тире — если правки их затрагивают, сдаётся `.docx` (флаг `--docx`). Конвейер пишет OOXML напрямую: pandoc из txt не различает ↵ и ¶.
