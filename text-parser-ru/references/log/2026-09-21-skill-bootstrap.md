# Создание скилла + smoke-тест чистки

Дата: 2026-09-21
Источник: синтетический текст в workspace (не боевой); объём: 7 строк
Результат: каркас скилла `scripts/clean_text.py` + тест-прогон

## Паттерны, найденные в тестовом тексте
- NBSP перед числом → обычный пробел (1)
- `¶` в конце строк → удалён/склейка (3)
- zero-width `\u200b` → удалён (1)
- двойные пробелы → одинарные (2)
- дефисный перенос `пе-\nренос` → склейка (1)
- перенос посреди слова `сто\nимность` → склейка без пробела

## Ключевые уроки (важнее самих замен)
1. ПОРЯДОК ПРАВИЛ решает: `¶\n`-склейку надо делать ДО удаления ¶ и ДО base-правил,
   иначе `\u00b6\n` → ` \n` и мягкая склейка `(?<=[\u0430-\u044f,])\n(?=[\u0430-\u044f])` не видит паттерн.
2. Кириллица в regex: `\u0430-\u044f` + `\u0451` (Ё), не «[а-я]» наугад — проверять на контрольных строках.
3. Склеенное пополам слово (`сто\nимность`, обе части со строчной, ни одна не самостоятельная) —
   отдельный тип: склеить БЕЗ пробела. Мягкая склейка через пробел даёт `сто имность` — это вопрос
   к пользователю, не молча.

## Спорные места и решения
- Нет боевого эталона от пользователя — тест синтетический; первая реальная задача покажет
  настоящие правила. Эталон = ТЗ, угадывать нельзя.

## До / после (1 короткий пример)

    ДО:
    механике, пе-
    ренос проверен.

    ПОСЛЕ:
    механике, перенос проверен.

## Скрипты
- `scripts/clean_text.py` — каркас: base-правила (мусорные символы) + кастомные `RULES` из
  `rules.py` поверх (ПЕРВЫМИ), счётчик вхождений каждого правила, `--audit` без записи.
