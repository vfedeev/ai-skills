# Каталог паттернов грязного текста

Сверочный список для шага 2 (разбор эталона). Паттерны сгруппированы по происхождению; regex-примеры — Python `re`, флаг `re.M` где имеет значение.

## Артефакты вёрстки (PDF/Word → текст)

| Симптом | Regex-подсказка | Обычное лечение |
|---|---|---|
| `¶` / `§` в конце строки (знак абзаца Word/InDesign) | `¶$`, `§\s*$` | удалить символ |
| Скрытые символы: soft hyphen, NBSP, zero-width | `\u00ad`, `\u00a0`, `\u200b-\u200f` | NBSP→обычный пробел (или удалить с переносом), soft hyphen удалить |
| Перенос с дефисом: `пе-\nренос` | `-\n` | склеить без пробела |
| Разрыв предложения переносом | `\n` посреди предложения (строка не на `.!?`) | склеить через пробел (проверить: если следующая строка со строчной — почти всегда склеить; с заглавной — вопрос, см. ниже) |
| Колонтитулы/номера страниц, вклеенные в текст | повторяющиеся короткие строки сверху/снизу каждой «страницы» | спросить: удалять или нет |
| Двойные пробелы после точки | `\.  +` | заменить на `. ` только если эталон это показывает |
| Табы / выравнивание пробелами | `\t`, `  +` | зависит от эталона |

## OCR-специфика

- `1` вместо `l`/`I`, `0` вместо `O`, `rn` вместо `m` — НЕ править молча: только если пользователь показал в эталоне.
- Склеенные слова: `привет,как` → после запятой/точки нужен пробел — проверять по эталону.
- Русские буквы ↔ латинские гомоглифы (`а`,`е`,`о`,`р`,`с`,`х`,`у`,`к`,`м`,`т`) — видно только скриптом (диапазон `\u0400-\u04FF` vs ASCII); спрашивать, если встречаются.

## Экспорты и дампы

- CSV/TSV-артефакты: кавычки-обёртки, `\r\n`, BOM `\ufeff` в начале файла.
- Markdown-мусор в «чистовом» тексте: `**`, `*`, `#`, `- ` маркеры — пользователь их часто удаляет руками; если эталон без них — удалять по всему тексту.
- HTML-сущности: `&nbsp;`, `&laquo;`, `&#39;` — декодировать (`html.unescape`), если эталон показывает нормальные кавычки.
- Кавычки-лапки vs "палочки": эталон диктует, какие оставить (`«…»` для русского).

## Контекстно-зависимые решения (почти всегда = вопрос)

1. Пустая строка между строками списка — склеивать в один список или это отдельные пункты?
2. Перенос перед заглавной буквой: новый абзац или середина предложения с автоматической капсом после OCR?
3. Двоеточие в конце строки + перенос: заголовок с подписью или разорванное предложение?
4. Повтор строки (заголовок дублируется в теле) — оставить первый или второй?
5. Строки, состоящие только из иероглифов: после `--remove` остаётся пустая строка — удалять целиком или оставлять разделителем? (дефолт: удалять вместе со строкой; спрашивать если между абзацами)

## Порядок применения правил (важно)

Сначала контекстные склейки/разбивки строк, потом удаление мусорных символов,
в конце — пробелы/пустые строки. Иначе `¶\n` после удаления ¶ превращается в
` \n` и склейка `\n` уже не срабатывает (проверено на тесте `scripts/clean_text.py`:
кастомные правила в нём применяются до базовых).

## Пресет CJK — иероглифы (scripts/strip_cjk.py)

Диапазоны для аудита/чистки: `\u4e00-\u9fff` (CJK-идеографы), `\u3400-\u4dbf` (расш. A), `\u3040-\u30ff` (хидрагана+катакана), `\uac00-\ud7af` (хангыль), `\u3000-\u303f` (CJK-пунктуация 。、《》), `\uff01-\uff5e` (полноширинные ，：！（）и fullwidth latin — MAППЯТСЯ в ASCII, не удаляются), идеографический пробел `\u3000`.

- Удалять только собственно письмена; пунктуация → обычная через маппинг (`--map`).
- **Mojibake ≠ иероглифы**: если `text.encode('latin-1').decode('utf-8')` даёт читаемый русский — битая кодировка, скрипт подсказывает; молча не лечить, в вопросы.
- Содержательные иероглифы (бренд, имя, цитата, URL) — не удалять молча: в вопросы.

## Пресет ТИПО — русская типографика (scripts/typo_ru.py)

- Кавычки: внешние `«…»`, вложенные `„…“`; прямые `"` → «ёлочки» только в явной паре; незакрытая кавычка НЕ угадывается — в отчёт и в вопросы; `"` после цифры (дюймы) и апостроф внутри слова не трогать.
- Тире: ` - ` / ` -- ` между словами → ` — `; диапазоны чисел `5 - 7`, `1990-2000` (только пробельные) → `–`; `...` → `…`. Дефис внутри слова не трогать; `- ` в начале строки (маркер списка) оставить.
- Пробелы: убрать перед `, . ; : ! ? % ) ]` и перед `»`; после `( [ «`; схлопнуть двойные. Пробел ПОСЛЕ знака при слипании (`привет,мир`) — НЕ типографика, это OCR-паттерн: только если показал эталон.
- Неразрывные пробелы у однобуквенных предлогов — только по явной просьбе: заметнее меняет текст.

## Регламент скорости (реализм из боевых задач 2026-09-21/22)

Исполнение — ОДИН вызов `scripts/pipeline.py` (см. SKILL.md шаг 3–5): профиль
инкапсулирует нормализацию+правила+ТИПО+чек+сборку docx. Цепочка отдельных
прогонов typo->rules->check->docx запрещена (4+ tool-call там, где нужен 1).
Tool-call бюджет задачи: 1 приём+анализ (одним скриптом), 1 clarify (если есть
спорные), 1 pipeline, 1 выдача. При знакомом профиле — приём+pipeline+выдача,
анализ не раздувать. Больше 8 — стоп: я либо перелатываю патчи вместо цельного
фикса, либо проверяю там, где достаточно exit 0 конвейера. При отладке
самого скилла (новый класс) бюджет мягче, но каждый найденный баг = правка
профиля/скрипта целиком, не латами.

Классы regex хранить СЫРЫМ содержимым (`W = r"\w\u0430-\u044f\u0451"`, оборачивать в `[{W}...]` только при подстановке) — иначе вложенный `[[...]]` молча даёт 0 матчей.

## Приём проверки гипотезы правила

Прежде чем применять правило ко всему тексту:

1. посчитай вхождения: `len(re.findall(PATTERN, text))` — 1-2 вхождения правило применять не стоит, это шум;
2. найди места, где правило НЕ сработает корректно (контекстные исключения) — если есть, они идут в список вопросов;
3. прогони правило на одном абзаце, сверь посимвольно с эталоном (`difflib`);
4. regex-проверка: `\u0430-\u044f` — не `[а-я]` из чата (кириллица в скошках живёт в диапазонах `\u0410-\u044f` + `\u0401\u0451` Ё; всегда проверяй regex на 2-3 контрольных строках до запуска по всему тексту).

## Проверенные правила проекта

**Как копить (важно):** каждое правило ниже — ПРОФИЛЬ класса задач, а не глобальный закон.
Ключ профиля — тип входа (афиша/расписание, статья, транскрипт, выгрузка из CRM…).
Перед применением профиля проверь, что вход того же класса: новые правила пишутся
с указанием класса, экстраполяция на чужие классы запрещена (для статьи дефис
в диапазоне времени и NBSP-типографика афиши не указ). Профиль, подтверждённый
на 2+ разных задачах одного класса, можно помечать как «класс ›». Если класс
новый — это снова шаг 2 (индукция по эталону), а не подгонка под существующий профиль.

### [класс: афиши/расписания] ДОМ-СТИЛЬ Владимира (эталон скриншотом Word 2026-09-22) — внутри этого класса ГЛАВНЕЕ пресета ТИПО
- Диапазон времени: **дефис без пробелов** `08:30-10:30` (не en/em dash!).
- Разделитель «время — название»: **среднее тире `–` с неразрывными пробелами** с обеих сторон (NBSP+–+NBSP).
- Названия в «ёлочках» — **склеены неразрывными пробелами внутри**: `«Шведский·стол»` (NBSP внутри кавычек).
- Площадка/возраст: без скобок, **отдельной СТРОКОЙ внутри того же абзаца** (Shift+Enter / `<w:br/>`, не ¶).
- **Перед КАЖДОЙ датой-заголовком (`31 декабря`, `1 января`…) — ровно один пустой абзац** (пустая строка исходника перед датой — не «мусор», а сознательный отбив). В исходнике число пустых строк перед датами плавает (1–3) — норма: одна.
- Между блоками внутри дня — никаких пустых абзацев; блок = один абзац (¶ в конце).
- Пустые строки в txt-вставке из Word = абзацы-¶; НЕ переносить эту пустоту в результат.
- Em dash `—` остаётся только внутри текста между словами (приложение/пояснение).
- Отдача для Word — .docx (каждый блок абзац, переносы `<w:br/>`), не .txt: txt не различает ¶ и Shift+Enter.

### [класс: афиши/расписания] Нарощения и время (задача `2026-09-21-afisha-raspisanie`)
- `N-ый/-ой` в порядковых (1-ый, 2-ой) → `N-й` (ГОСТ). Дефис в `1-й этаж` сохраняется.
- Время: `чч.мм` → `чч:мм`; оформление диапазона/разделителя — по ДОМ-СТИЛЮ выше (дефис в диапазоне!), не по ГОСТ-пресету.
- В афишах/расписаниях: скобки у коротких названий-локаций (Ресторан, зал, шатёр, Ресепшн…) снимаются, место — отдельной строкой с заглавной; скобки в ремарках-предложениях остаются.

### Регресс-чек (встроен в pipeline, exit 1 = FAIL; ШАБЛОН, нули из текущей задачи)
Для зрелого профиля (опробован на задаче+) exit 0 достаточен — сдавать без
дополнительных сверок. Развёрнутая проверка (дифф с эталоном глазами, nonprintables)
— при первом применении нового класса или по явному запросу.
Список нулей — это паттерны, которые задача ОБЕЩАЛА устранить (списки/regex из её
правил; для афиш это было `\((Ресторан|Каминный|…)`, `\d-[ыо]й`, `\d \+`, `\.\.`,
`\S[ ]{2,}\S`). Плюс **дословная сверка с эталоном на уровне НЕПЕЧАТАЕМЫХ символов**: если эталон задан скриншотом Word — проверять знаки ¶ vs ↵, дефис vs – vs —, обычные vs неразрывные пробелы. Совпадение «на глаз по тексту» НЕ считается проверкой (урок 2026-09-22: вычитал дефис за тире, NBSP не увидел, структуру абзацев потерял — пользователь открыл nonprintables и вернул работу).
